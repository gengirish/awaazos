Bol. Bill. Becho.

A chai-wala in Hyderabad taps an orange button and says “do samosa aur ek chai.” Less than two seconds later, the customer’s phone is showing a UPI QR code. This module follows every single thing that happens in between.

What this thing actually does

AwaazOS is a point-of-sale system for India’s 25 million micro-merchants — chai stalls, dosa carts, paan shops, kirana stores. The kind of place where the owner takes orders verbally in Hindi or Telugu, and writing them down by hand loses about 15–20% of revenue every month.

The pitch is one line: tap a button, speak the order in any Indian language, get a bill and a UPI QR code. No typing. No menus to navigate. No English required.

🎙️
The whole product, in one sentence

If a chai-wala can’t take their first 100 voice orders without thinking, every other feature is a distraction. The codebase is organised around protecting that one experience.

A backstage tour

Imagine you’ve just watched a 90-minute play. The acting was great, but you have no idea what the stagehands were doing behind the curtain — the lighting cues, the prop swaps, the quick costume changes that made it all feel effortless.

This module is that backstage tour for one specific scene: the moment a vendor speaks an order. Everything else in the course unpacks one of these stagehands in detail.

1
Vendor taps the orange mic

An 80×80 pixel button on a phone screen — large enough for a thumb covered in dosa batter.

2
The phone listens

For English & Hindi, the browser does the speech-to-text for free. For Telugu / Kannada / Tamil, the audio gets sent to Sarvam AI.

3
Claude turns the words into items

The transcript (“do samosa aur ek chai”) plus this vendor’s exact menu goes to Claude Haiku 4.5. It returns structured items: { samosa: 2, chai: 1 }.

4
The cart fills on screen

The vendor sees the items appear, taps Collect Payment, and a UPI QR code fills the screen.

5
Customer scans, pays, walks away

The vendor taps Mark as Paid. Five database writes commit together as one. A WhatsApp receipt gets queued. The next order can start.

All five steps complete in roughly 1.8 seconds on a median phone in Hyderabad. The next screens unpack each step.

The mic button — small code, lots of states

The button itself is one of the most-touched pieces of the whole product. It has six visual states (idle, listening, transcribing, parsing, success, error) and every one is announced to screen readers. Here’s the core of it.

CODE · components/pos/VoiceOrderButton.tsx 
<button
  type="button"
  onClick={() => {
    if (state === "listening") stopListening();
    else startListening();
  }}
  aria-label={label}
  aria-pressed={state === "listening"}
  className={cn(
    "relative flex h-20 w-20 shrink-0 ...",
    state === "idle" && "bg-primary ...",
    state === "listening" &&
      "bg-destructive ... motion-safe:animate-pulse",
  )}
>
PLAIN ENGLISH

Make a clickable button on the page.

When tapped, ask: am I already listening? If yes, stop. If no, start.

Tell screen readers what the button currently means right now (idle? listening?). The label changes with the state.

Tell screen readers whether the button is “pressed” (which is what listening feels like).

Pick the visual look based on the state. Idle = solid orange. Listening = red with a pulse animation, but only if the user hasn’t turned animations off.

The pulse only animates for users who haven’t enabled the “reduce motion” accessibility setting on their phone.

♿
Why every state has a label

About 12% of Indian phone users have a vision impairment of some kind. Screen readers rely on aria-label and aria-pressed to narrate what just happened — without them, a blind chai-wala can’t use the product. Add accessibility on day one.

A budget for every step

Voice products live or die on latency. If a vendor has to wait three seconds after speaking, they’ll go back to writing on paper. This codebase has a published time budget for every leg of the journey.

🎤

Browser → Server

~80 ms median. Just the network hop from the vendor’s phone to Vercel.

🗣️

Speech → Text

~1.2 s for Indic languages via Sarvam. Free & instant for English/Hindi via the browser.

🧠

Text → Items

~350 ms for Claude Haiku to match the menu. Roughly the time it takes to blink three times.

💾

Save the sale

~90 ms to atomically write all five rows to Postgres.

Add it up: about 1.8 seconds from speech to QR code on a typical day. P95 (the slowest 5% of requests) tops out around 3.7 seconds.
