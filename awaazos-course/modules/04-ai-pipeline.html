04

Speech becomes structure

When the vendor says “sat samosa, do chai, ek vada pav, pyaaz wala”, the computer first hears literal noise. By the time the cart fills, that noise is a structured list: [{ id, name, qty, price }, …]. This module follows the four steps that bridge those two worlds.

A translator with a sticky-note menu

Imagine a market translator standing next to a vendor. They don’t speak the customer’s language perfectly — they need a cheat sheet. So the vendor sticks a copy of the menu next to them, with each item highlighted.

When a customer says “two of those crispy onion ones,” the translator glances at the sheet, points at aloo bhujia, and tells the vendor “they want 2× aloo bhujia.”

The cheat sheet is the cached menu. The translator is Claude. The pointing is tool-use. The whole module is making this metaphor literal.

📌
Why every step in this pipeline costs money

The voice path is the per-order unit cost of the product. AwaazOS charges only ₹299/month, so the engineering choices here aren’t cosmetic — they’re what makes the pricing possible.

Step 1: pick the right speech-to-text engine

Two paths, decided by language. English and Hindi go through the browser’s built-in Web Speech API. Telugu, Kannada, and Tamil go to Sarvam.

📱

Web Speech (en-IN, hi-IN)

On-device. Free. No audio ever leaves the phone. The browser hands us back a text string in ~600 ms.

🌐

Sarvam Saaras v2 (te, kn, ta)

Server round-trip. The browser records 5–12 seconds of audio, ships it to /api/ai/transcribe, which forwards it to Sarvam. Costs roughly 1.2 seconds and a paisa per call.

CODE · hooks/useVoiceOrder.ts 
const SARVAM_LANGS = new Set(["te-IN", "kn-IN", "ta-IN"]);
const WEBSPEECH_LANGS = new Set(["en-IN", "hi-IN"]);

if (WEBSPEECH_LANGS.has(voiceLang)) {
  const Ctor = window.SpeechRecognition ?? window.webkitSpeechRecognition;
  if (!Ctor) { setState("error"); return; }
  const recognition = new Ctor();
  recognition.lang = voiceLang;
  recognition.start();
}

if (SARVAM_LANGS.has(voiceLang)) {
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const mr = new MediaRecorder(stream, { mimeType });
  mr.start();
  // 12-second hard timeout — even if vendor forgets to stop
  setTimeout(() => mr.stop(), 12_000);
}
PLAIN ENGLISH

Define two sets of languages — one handled in-browser, one handled by Sarvam.

For English/Hindi: ask the browser if it has a built-in speech recogniser. (Some don’t.)

If yes, kick it off in this language. The text comes back via callbacks.

For Indic languages: ask the OS for microphone access. The browser pops the “allow microphone?” prompt.

Start recording into a Blob (a chunk of audio in memory).

Set a hard 12-second cap so we don’t end up uploading a 10-minute clip if the vendor forgets to tap stop.

Step 2 & 3: cache the menu, force a tool call

Once we have the transcript, the menu plus transcript go to Claude. Two engineering choices make this cheap and reliable:

A
Cache the menu

For a 30-item menu, the JSON is ~2KB. Marking it cache_control: ephemeral tells Anthropic “this part doesn’t change between calls — reuse it.” The cache lives 5 minutes. During the lunch rush, every request after the first one pays ~75% less for that block.

B
Force a tool call

Instead of asking Claude for free-form JSON (which sometimes hallucinates trailing commas), we declare a add_items “tool” with a strict schema. Claude is forced to fill in that exact shape, so the answer is structured by construction.

CODE · lib/anthropic.ts 
const message = await modelClient.messages.create({
  model: modelName,
  max_tokens: 512,
  temperature: 0.1,
  system: ORDER_PARSE_SYSTEM,
  tools: [ADD_ITEMS_TOOL],
  tool_choice: { type: "tool", name: "add_items", disable_parallel_tool_use: true },
  messages: [
    {
      role: "user",
      content: [
        {
          type: "text",
          text: `Authoritative menu (JSON):\n${menuJson}`,
          cache_control: { type: "ephemeral" },
        },
        {
          type: "text",
          text: `Customer transcript (${lang}):\n${transcript}`,
        },
      ],
    },
  ],
});
PLAIN ENGLISH

Send a message to Claude. The model name is passed in — same code path for Haiku and Sonnet.

Cap the answer at 512 tokens. Order parsing answers are tiny.

Set temperature to 0.1 — we want consistent, boring, deterministic outputs.

Give Claude one tool it’s allowed to use: add_items. The schema lives in a separate constant.

Force Claude to call this exact tool, exactly once. No free-form text. No parallel calls.

First content block: the vendor’s menu as JSON. The magic line is cache_control: ephemeral.

That line tells Anthropic “remember this block” for the next 5 minutes. Subsequent requests during a busy lunch rush pay ~75% less for the same menu.

Second content block: the transcript itself. This part changes every call, so it’s NOT cached.

Step 4: when does the senior translator get called?

Haiku covers ~85% of orders. The other 15% — long, code-mixed, ambiguous — get escalated to Sonnet. The decision happens in one small function.

CODE · app/api/ai/parse-order/route.ts 
function shouldEscalate(
  result: Awaited<ReturnType<typeof parseOrderWithClaude>>,
  transcript: string,
): boolean {
  const words = wordCount(transcript);
  if (result.items.length === 0 && words > 3) return true;
  if (result.confidence === "low" && result.unmatched.length > 0) return true;
  return false;
}
PLAIN ENGLISH

A function that returns “true” if we should re-run the parse with the smarter (and pricier) model.

It looks at Haiku’s answer and the original transcript.

First trigger: Haiku found nothing, but the customer said more than 3 words. They probably ordered something — let Sonnet take another look.

Second trigger: Haiku flagged low confidence AND there are phrases it couldn’t map. Sonnet’s extra reasoning is worth the cost here.

Otherwise, trust Haiku. Sonnet stays asleep.

💡
A pattern with a name

This is called a cascade or two-tier model routing. Cheap-and-fast for the 85% case, smart-and-slow for the 15% edge cases. You can apply this to any AI feature: try the small model first, escalate only when needed. Easy to ask AI for: “add a confidence-based escalation from Haiku to Sonnet for this endpoint.”

Indic numerals — the prompt’s secret sauce

Vendors don’t say “two” — they say do, rendu, eradu, onnu. The model needs to know these mean numbers. So the system prompt teaches it.

CODE · lib/anthropic.ts (system prompt excerpt) 
Normalize Indic numerals:
- hi: ek=1, do=2, teen=3, char=4, paanch=5
- te: okati=1, rendu=2, moodu=3, naalugu=4, aidu=5
- kn: ondu=1, eradu=2, mooru=3, naalku=4, aidu=5
- ta: onnu=1, rendu=2, moonu=3, naangu=4, anju=5

Put any phrase you could NOT confidently map into unmatched.
confidence = low if unmatched.length > 0 OR the transcript is ambiguous.
PLAIN ENGLISH

A small, hand-crafted lookup table embedded in the system prompt.

Each line is one language — spoken numerals 1 through 5 in Hindi, Telugu, Kannada, and Tamil.

The model uses these as anchor points. (LLMs are good at extrapolating beyond explicit examples.)

Crucial rule: if any phrase doesn’t map to a menu item, list it in unmatched rather than guessing wrong.

If anything ended up in unmatched, the model must mark confidence as “low” — which (per the previous screen) triggers escalation to Sonnet.

A note on what doesn’t go to Claude

🔒
Customer phone numbers never reach the LLM

Only the transcript and menu JSON are sent to Anthropic. Customer phone, name, and UPI reference are scrubbed at the boundary — they exist in Postgres for re-sending receipts, but they never appear in a prompt or a log line. This is a rule baked into the project’s Cursor rules — meaning the AI coding assistant itself enforces it on every PR.
